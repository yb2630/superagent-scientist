# TileCpp

TileCpp is a C++23 library for generic FP8 quantization. It separates the
numerical format, the memory layout and the execution policy behind small
concepts, so the same kernels can be reused sequentially, in parallel, or from
the coroutine/sender batch interface planned for later milestones.

**Milestone 1 (this revision):** repository scaffold, owning storage and
non-owning padded row-major matrix views, scalar FP8 **E4M3FN** quantization
with **per-row scaling**, `std::expected`-based validation, a dependency-free
test suite, and an independent Python reference implementation with committed
deterministic test vectors. No SIMD backend, coroutine layer or benchmark
harness yet.

## Requirements

- A C++23 compiler (tested with Apple clang 21 / libc++).
- CMake >= 3.25 and Ninja (Make also works).
- Python 3.9+ only for regenerating the reference vectors; the library and its
  tests have no external dependencies and need no network access.

## Build and test

```sh
cmake -S . -B build -G Ninja -DCMAKE_BUILD_TYPE=Debug
cmake --build build
./build/tests/tilecpp_tests
# or, when ctest is on PATH:
ctest --test-dir build --output-on-failure
```

Sanitizer configurations (separate build directories):

```sh
# AddressSanitizer + UndefinedBehaviorSanitizer
cmake -S . -B build-asan -G Ninja -DCMAKE_BUILD_TYPE=Debug \
      -DTILECPP_SANITIZE=ON
cmake --build build-asan
ctest --test-dir build-asan --output-on-failure

# ThreadSanitizer, reserved for the concurrency milestone
cmake -S . -B build-tsan -G Ninja -DCMAKE_BUILD_TYPE=Debug \
      -DTILECPP_SANITIZE_THREAD=ON
cmake --build build-tsan
ctest --test-dir build-tsan --output-on-failure
```

`TILECPP_SANITIZE` and `TILECPP_SANITIZE_THREAD` are mutually exclusive.
`-DTILECPP_WERROR=ON` turns the project warning set into errors.

## Quick example

```cpp
#include <tilecpp/tilecpp.hpp>

#include <cstdint>
#include <cstdio>

int main() {
  constexpr std::size_t rows = 2;
  constexpr std::size_t columns = 3;

  tilecpp::owning_buffer<float> input_storage(rows * columns);
  input_storage[0] = 1.0F;
  input_storage[1] = -2.0F;
  // ... fill remaining values

  const auto input = tilecpp::matrix_view<const float>::create(
      input_storage.span(), rows, columns, columns);
  if (!input) {
    std::fprintf(stderr, "%s\n", tilecpp::format(input.error()).c_str());
    return 1;
  }

  tilecpp::owning_buffer<std::uint8_t> quantized_storage(rows * columns);
  const auto quantized = tilecpp::matrix_view<std::uint8_t>::create(
      quantized_storage.span(), rows, columns, columns);
  tilecpp::owning_buffer<float> scales(rows);

  const auto status = tilecpp::quantize_rows(*input, *quantized, scales.span());
  if (!status) {
    std::fprintf(stderr, "%s\n", tilecpp::format(status.error()).c_str());
    return 1;
  }
  // quantized_storage now holds one E4M3FN byte per element; scales holds
  // one per-row scale factor.
}
```

## Numerical conventions (summary)

- Format: OCP/ONNX **E4M3FN** (sign 1, exponent 4 with bias 7, mantissa 3);
  largest finite value `448`; no infinities; `0x7F`/`0xFF` are NaNs.
- Encoding: round-to-nearest, ties-to-even; saturating overflows to `±448`;
  NaN and `±Inf` encode to the canonical NaN `0x7F`; signed zero is preserved.
- Decoding is exact: every finite E4M3FN value is exactly representable as a
  `float`.
- Scaling: one scale per row, `max_abs(finite row values) / 448`; an all-zero
  row uses scale `1`. Padding and non-finite values do not influence the scale.
  The scaling policy interface is block-aware, so per-block scaling can be
  added without changing the numerical or layout code.
- All runtime dimension, stride, storage, shape and scale errors are reported
  through `std::expected`; incompatible types and policies are rejected at
  compile time by concepts.

The full specification is in [docs/design.md](docs/design.md).

## Repository layout

```text
include/tilecpp/       public headers (policies, views, kernels)
src/                   compiled library sources
tests/                 C++ test suite and committed reference vectors
tests/data/            deterministic vectors generated by the Python reference
tools/                 independent Python reference and vector generator
benchmarks/            skeleton for the milestone-4 benchmark harness
docs/design.md         architecture, numerical specification and milestone plan
```

Regenerate the reference vectors (only needed when the reference model or the
vector format changes):

```sh
python3 tools/generate_test_vectors.py
```

## Milestones

1. Repository scaffold, scalar E4M3FN quantization with per-row scales, Python
   reference vectors and sanitizer-tested unit tests. *(this revision)*
2. Per-block scaling policy and the SIMD backend, including the
   specialized-vs-generic comparison.
3. `stdexec`/coroutine batch interface, thread-pool execution policy,
   cancellation and ownership tests, and the sequential/sender/coroutine
   comparison.
4. Benchmark harness and measurements (throughput, p50/p95 latency, peak
   memory, allocation counts), design-trade-off report and fused SwiGLU
   stretch goal.
